# WordPress Coding Standards

## Purpose

This document defines the official WordPress coding standards that SquirrelForge must follow for all generated PHP, JavaScript, CSS, and HTML code. Adherence to these standards ensures code is readable, consistent, and maintainable.

This is a summary. The agent should refer to the official WordPress Coding Standards Handbooks for complete details.

---

## PHP Standards

### Formatting

- **Indentation:** Use tabs, not spaces.
- **Braces:**
  - Use the "one true brace style" (OTBS). Braces for classes and functions start on the same line.
    ```php
    class My_Class {
        public function my_function() {
            // ...
        }
    }
    ```
  - For control structures (`if`, `else`, `for`, `while`, `switch`), the opening brace is on the same line, but there is a space before it.
    ```php
    if ( $condition ) {
        // ...
    }
    ```
- **Spaces:** Use spaces around operators (`=`, `+`, `-`, `*`, `/`, `.`), after commas, and in control structure parentheses.
- **Line Endings:** Use Unix-style line endings (LF).

### Naming Conventions

- **Variables & Functions:** Use lowercase letters and separate words with underscores (snake_case).
  ```php
  $my_variable = 'value';
  function my_plugin_function() {
      // ...
  }
  ```
- **Classes & Traits:** Use PascalCase (title case with words capitalized and no separators). The filename should be `class-class-name.php`.
  ```php
  class My_Plugin_Admin {
      // ...
  }
  ```
- **Constants:** Use all-uppercase letters with underscores.
  ```php
  define( 'MY_PLUGIN_VERSION', '1.0.0' );
  ```
- **Prefixing:** All functions, classes, and global variables must be prefixed with a unique identifier to prevent conflicts.

### Best Practices

- **Yoda Conditions:** Use Yoda conditions for comparisons to prevent accidental assignments. The literal value comes first.
  ```php
  if ( true === $value ) {
      // ...
  }
  if ( 'my-string' === $text ) {
      // ...
  }
  ```
- **Quotes:** Use single quotes for strings unless you need to evaluate variables within the string.
- **Self-Closing PHP Tags:** In files containing only PHP, the closing tag `?>` must be omitted.
- **PHPDoc:** All classes, functions, and methods must have PHPDoc blocks describing their purpose, parameters, and return values.

## JavaScript Standards

### Formatting

- **Indentation:** Use tabs.
- **Spacing:** Use spaces around operators and after commas.
- **Braces:** Opening braces go on the same line.
- **Semicolons:** Always use semicolons to terminate statements.

### Naming Conventions

- **Variables & Functions:** Use camelCase.
  ```javascript
  const myVariable = 'value';
  function myFunction() {
      // ...
  }
  ```
- **Constructors/Classes:** Use PascalCase.

### Best Practices

- **Quotes:** Use single quotes for strings.
- **Strict Mode:** Use `'use strict';` where appropriate.
- **`wp.i18n`:** Use the `wp.i18n` package for all translatable strings.

---

## CSS Standards

### Formatting

- **Indentation:** Use tabs.
- **Selectors:** Place each selector on its own line.
- **Properties:** Place each property declaration on its own line, indented one level.
- **Spacing:** Use a space after the colon in a property declaration.

```css
.my-class {
	color: #333;
	font-weight: 600;
}
```

### Naming Conventions

- **Selectors:** Use lowercase kebab-case.

---

## HTML Standards

### Formatting

- **Indentation:** Use tabs to reflect the logical structure.
- **Quotes:** Always use double quotes for attributes.
- **Self-Closing Elements:** Self-closing tags should have one space before the closing slash (e.g., `<hr />`).
