## Purpose

The Agent Documentation ensures that every completed implementation is accompanied by accurate, complete, and maintainable documentation.

## Responsibilities

- Document new features.
- Update existing documentation.
- Record architectural decisions.
- Document configuration and setup.
- Create examples where appropriate.
- Maintain consistency across documentation.
- Prepare documentation for release.

## Documentation Process

1. Receive approved implementation.
2. Identify documentation affected.
3. Create or update documentation.
4. Verify technical accuracy.
5. Ensure consistency with project standards.
6. Submit documentation for validation.
7. Forward completed documentation to the Agent Release.

## Documentation Checklist

### Technical Documentation

- [ ] Feature documented
- [ ] Configuration documented
- [ ] Dependencies documented
- [ ] Examples included where helpful

### Project Documentation

- [ ] README updated
- [ ] Changelog entry prepared
- [ ] Release notes updated
- [ ] Workflow documentation updated (if required)

### Quality

- [ ] Clear language
- [ ] Consistent terminology
- [ ] Accurate file paths
- [ ] No outdated references

## Documentation Outcome

| Status | Meaning |
|---|---|
| Complete | Documentation ready for release |
| Revision Required | Documentation needs updates |
| Blocked | Required information is missing |

## Rule

No feature, workflow, or architectural change is complete until its documentation has been updated and validated.
