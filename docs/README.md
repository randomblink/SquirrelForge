# SquirrelForge Documentation

## Purpose

This directory contains the governed engineering knowledge produced around the SquirrelForge AI-agent architecture and its WordPress diagnostic catalog. The repository-wide architecture remains defined by [`ARCHITECTURE.md`](../ARCHITECTURE.md); this page routes readers through the evidence and governance under `docs/`.

## Reading Order

1. Read [`CONTRIBUTING.md`](../CONTRIBUTING.md) for evidence-first working rules.
2. Read [`standards/`](standards/README.md) before creating or revising a governed artifact.
3. Use [`knowledge/`](knowledge/README.md) for the WordPress error catalog and runtime verifications.
4. Use [`reviews/`](reviews/README.md) to inspect the evidence and decisions behind approved artifacts.
5. Use [`baselines/`](baselines/README.md) for formal baseline declarations.
6. Use [`engineering/`](engineering/README.md) for active plans and framework observations.
7. Use [`validation/`](validation/README.md) for validation records outside the WP-VERIFICATION series.

## Directory Map

| Directory | Contains | Read when |
|---|---|---|
| [`standards/`](standards/README.md) | Specifications, methodologies, templates, and taxonomies | Determining what rules govern work |
| [`knowledge/`](knowledge/README.md) | Certified WP-ERROR entries and runtime-verification evidence | Diagnosing or verifying WordPress behavior |
| [`reviews/`](reviews/README.md) | Author, independent, consistency, baseline, and governance reviews | Auditing why an artifact was approved or corrected |
| [`baselines/`](baselines/README.md) | Framework baseline declarations | Establishing the certified framework state |
| [`engineering/`](engineering/README.md) | Plans and framework observations | Understanding active work and known limitations |
| [`validation/`](validation/README.md) | Specialized validation artifacts | Examining validation outside the knowledge-verification track |

## Placement Rule

Place new material with the authority class that owns it. Do not create a new directory, taxonomy, identifier series, or competing architecture document merely for convenience; establish evidence and governance need first.
