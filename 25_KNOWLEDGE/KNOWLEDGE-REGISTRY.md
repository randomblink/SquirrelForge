# SquirrelForge Knowledge Registry

## Purpose

The Knowledge Registry serves as the authoritative catalog of all knowledge assets used within SquirrelForge, ensuring that each asset has a unique identity, ownership, source, classification, trust level, lifecycle state, and relationship context.

---

## Responsibilities

- Register knowledge assets.
- Assign unique knowledge identifiers.
- Record source and ownership.
- Classify knowledge by type and purpose.
- Track trust levels.
- Maintain lifecycle status.
- Map relationships between knowledge assets.
- Support knowledge discovery.

---

## Registry Process

1. Receive knowledge registration.
2. Assign unique Knowledge ID.
3. Validate required metadata.
4. Record source and ownership.
5. Classify knowledge asset.
6. Assign trust level.
7. Record lifecycle state.
8. Publish registry entry.

---

## Knowledge Types

| Type | Description |
|---|---|
| Document | Structured written reference |
| Artifact | Generated workflow output |
| Rule | Operational or governance rule |
| Decision | Recorded reasoning outcome |
| Memory | Persistent or temporary agent memory |
| Dataset | Structured data source |
| Integration Record | Knowledge from external systems |
| Observation | Operational event or measurement |

---

## Registry Record

| Field | Description |
|---|---|
| Knowledge ID | Unique identifier |
| Name | Knowledge asset name |
| Type | Knowledge category |
| Source | Originating source |
| Owner | Responsible component |
| Trust Level | Low / Medium / High / Authoritative |
| Lifecycle Status | Draft / Validated / Active / Deprecated / Archived |
| Version | Current version |
| Related Assets | Linked knowledge references |

---

## Trust Levels

| Trust Level | Meaning |
|---|---|
| Low | Unverified or experimental knowledge |
| Medium | Partially reviewed knowledge |
| High | Validated and reliable knowledge |
| Authoritative | Approved source of truth |

---

## Governance Principles

- Every knowledge asset must have one unique identifier.
- Source information must be recorded.
- Ownership must be explicit.
- Trust level must be assigned before use.
- Related assets should be linked when relevant.
- Registry entries must remain discoverable and auditable.

---

## Rule

No knowledge asset may be used for reasoning, planning, validation, or execution unless it has been registered in the Knowledge Registry with source, owner, lifecycle status, and trust level.
