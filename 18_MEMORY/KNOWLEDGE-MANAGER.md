## Purpose

The Knowledge Manager captures, organizes, and reuses knowledge generated during project execution to improve future work.

## Responsibilities

- Store reusable implementation patterns.
- Record lessons learned.
- Capture workflow improvements.
- Maintain architectural decisions.
- Track coding standards and best practices.
- Preserve validated solutions for future reuse.
- Support continuous improvement across projects.

## Knowledge Sources

- Reflection Engine
- Completed workflows
- Validated implementations
- Project documentation
- Architecture decisions
- Coding standards
- User feedback

## Knowledge Categories

| Category | Description |
|---|---|
| Patterns | Reusable implementation patterns |
| Decisions | Architectural and design decisions |
| Standards | Coding and documentation standards |
| Workflows | Improved workflow practices |
| Templates | Reusable document templates |
| Lessons | Lessons learned from completed tasks |
| Solutions | Validated fixes for recurring problems |

## Knowledge Lifecycle

1. Capture new knowledge.
2. Classify it into a category.
3. Validate its accuracy.
4. Store it in the knowledge base.
5. Make it available to future workflows.
6. Review periodically for relevance.
7. Archive obsolete knowledge.

## Knowledge Record

| Field | Description |
|---|---|
| ID | Unique identifier |
| Title | Short descriptive name |
| Category | Knowledge category |
| Source | Origin of the knowledge |
| Description | Detailed explanation |
| Validation | Pending / Validated / Archived |
| Date Added | Creation date |
| Last Reviewed | Most recent review date |

## Rule

Only validated, reusable knowledge may be added to the knowledge base. Obsolete or superseded knowledge should be archived rather than deleted.
