## Purpose

Project Memory stores long-lived information that is unique to a specific project, preserving architectural decisions, project conventions, milestones, and historical context.

## Responsibilities

- Record project architecture.
- Store project-specific standards.
- Preserve design decisions.
- Track milestones.
- Record major implementation changes.
- Maintain project history.
- Support future maintenance and enhancement.

## Project Memory Contents

| Item | Description |
|---|---|
| Project Name | Name of the project |
| Architecture | Overall system design |
| Conventions | Naming, structure, and coding conventions |
| Decisions | Important technical decisions |
| Milestones | Major completed milestones |
| Risks | Known project risks |
| Dependencies | Long-term project dependencies |
| Notes | Additional project context |

## Recording Process

1. Capture project information.
2. Validate major decisions.
3. Record completed milestones.
4. Update architectural history.
5. Record dependency changes.
6. Index the project record.
7. Preserve for future reference.

## Usage

Project Memory supports:

- Future feature development
- Bug investigation
- Architectural consistency
- Project onboarding
- Maintenance planning
- Long-term evolution

## Rule

Project Memory should contain only information that is specific to the current project. General knowledge, reusable patterns, and best practices belong in Semantic Memory.
