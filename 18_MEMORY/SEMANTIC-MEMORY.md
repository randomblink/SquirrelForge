## Purpose

Semantic Memory stores validated, reusable knowledge that is independent of any single task or project.

## Responsibilities

- Store coding standards.
- Store architectural patterns.
- Store reusable workflows.
- Store best practices.
- Store validated implementation patterns.
- Store reusable solutions.
- Support intelligent planning and execution.

## Knowledge Categories

| Category | Description |
|---|---|
| Standards | Coding, documentation, and project standards |
| Patterns | Reusable implementation patterns |
| Architecture | Proven architectural approaches |
| Workflows | Validated workflow improvements |
| Templates | Reusable document and project templates |
| Best Practices | General recommendations |
| Solutions | Validated fixes for recurring problems |

## Knowledge Record

| Field | Description |
|---|---|
| Knowledge ID | Unique identifier |
| Category | Knowledge classification |
| Title | Short descriptive title |
| Description | Detailed explanation |
| Source | Origin of the knowledge |
| Validation | Pending / Validated / Archived |
| Related Workflows | Associated workflows |
| Last Reviewed | Most recent review date |

## Promotion Process

1. Receive candidate knowledge from the Reflection Engine or Knowledge Manager.
2. Verify that it is reusable.
3. Confirm validation.
4. Classify the knowledge.
5. Store it in Semantic Memory.
6. Index it for future retrieval.

## Rule

Semantic Memory should contain only generalized, validated knowledge that can improve future projects. Project-specific information belongs in Project Memory.
